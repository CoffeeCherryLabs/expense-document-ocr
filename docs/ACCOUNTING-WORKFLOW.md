# 회계 업무 화면과 자동 접수

지출 관리대장이 회계 업무의 기준 데이터입니다. Drive는 원본 보관,
증빙 수신함은 파일 접수와 지출 연결, GitHub는 자동화 코드와 실행 기록을 맡습니다.

## 담당자에게 표시할 정보

기본 표는 건명, 금액, 사용일, 지출자, 보완 안내, 처리 상태만 표시합니다.
회계 처리 대기와 처리 완료는 별도 뷰에서 확인합니다.
회계 완료는 처리 상태 `처리 완료`와 회계 처리일을 함께 확인합니다.
자동 접수·OCR 완료·사전검토 통과만으로 결재나 회계 완료로 바꾸지 않습니다.

`보완 안내`는 자동화가 제안하는 다음 작업입니다.
담당자가 작성한 요청은 기존 `보완·반려 사유`에 기록합니다.
지출자가 입력한 목적·참석자, 담당자의 결재·회계 기록은 자동 판독으로 덮어쓰지 않습니다.
업무 목적과 회사 운영비/과제 구분은 사람에게 확인하며 과제를 임의로 배정하지 않습니다.

## 증빙 수신함

운영 데이터 소스에 다음 속성이 필요합니다.

- `확인 유형` select: 참고 사진, OCR 보완, 정보 보완, 접수 완료
- `조치 상태` select: 확인 대기, 보완 대기, 정리 완료
- `처리 안내` rich_text

관리대장에는 `보완 안내` rich_text가 필요합니다.
기존 데이터 소스에 이 속성을 추가한 뒤 코드를 배포합니다.
기존 DB, 원본 링크와 연결 지출을 재사용하며 새 지출 DB를 만들지 않습니다.

`정리 완료`는 파일 분류·연결 작업이 끝났다는 뜻입니다. 회계 승인과는 별개입니다.
자동 OCR 값은 보존하며 사람이 대조한 내용과 조치 상태를 분리합니다.
같은 거래의 영수증·명세표·사진은 하나의 지출에 연결합니다.
참고 사진은 별도 금액으로 합산하지 않습니다.

## 상세 정보와 접근권한

OCR JSON, 원문, 신뢰도, 해시, 오류 코드와 연구비 체크리스트는 기본 표와 페이지에서 숨깁니다.
기존 기록·원본 파일은 펼쳐서 확인하는 영역에 보존합니다.
속성 숨김은 화면 정리이며 접근권한 제한이 아닙니다. 기존 공유권한은 변경하지 않습니다.
외부 회계 담당자에게 공유할 때는 필요한 페이지·원본의 접근권한을 별도로 설정해야 합니다.

## 캘린더와 지출 통계

`지출 한눈에 보기`는 같은 관리대장의 연결된 뷰를 사용합니다.
상단은 전체 사용액, 회계 완료액, 미처리 건수를 두 줄로 표시합니다. 상세 합계와 그래프는 펼쳐 확인합니다.
캘린더는 별도 집계 자료에서 날짜·지출자별 합계 한 줄을 표시합니다.
원거래의 제목·증빙 사진은 기본 캘린더에 나열하지 않습니다.
원화만 합산하고 취소·반려를 제외합니다. 미확정 결제는 확인 필요 그룹에 포함합니다.
파일 수신함의 영수증·사진 수를 지출 건수로 합산하지 않습니다.

그래프용 `집계 월` select와 `집계 결제방식` select가 필요합니다.
월은 한국 시간의 사용일 기준입니다. 새 초안 생성과 정기 동기화에서 갱신하며,
사람이 날짜·결제 방식을 수정하면 다음 동기화에서 집계 그룹도 반영합니다.
원본 날짜·금액·결제 방식·회계 승인을 변경하지 않습니다.

### 하루·지출자별 집계 자료

`DAILY_SUMMARY_DATA_SOURCE_ID`는 관리대장과 구분된 읽기용 집계 자료입니다.
속성은 `하루 사용` title, `사용일` date, `지출자` people, `하루 합계` number(won),
`지출 건수` number, `연결 지출` relation(관리대장), `집계키` rich_text, `결제 요약` rich_text, `표시 이름` rich_text입니다.
달력은 제목의 원화 합계와 짧은 표시 이름만 표시합니다. 제목 줄바꿈을 켜고 페이지 아이콘을 숨깁니다. 항목을 열면 원거래 연결과 결제 요약을 확인합니다.
한국 시간의 사용일과 실제 지출자 ID를 그룹 키로 쓰며, 지출자가 없는 거래는 확인 필요로 구분합니다.
여러 지출자가 지정된 경우 공동 그룹으로 묶어 금액을 중복 배분하지 않습니다.
`KNOWN_CARD_DISPLAY_NAME`은 등록한 카드 소유자 ID의 화면 표시 별칭입니다. 카드 매칭이나 실제 사용자 지정에는 영향을 주지 않습니다.
사람 이름과 실제 거래 데이터를 공개 저장소에 기록하지 않고 런타임 설정과 Notion에 보관합니다.

새 영수증이 없어도 모든 일반 동기화에서 집계를 갱신합니다. 같은 그룹 키는 갱신하고
변경 없는 집계는 쓰지 않습니다. 날짜·지출자 수정 및 취소·반려는 다음 실행에 반영합니다.
없어진 그룹은 자동화가 만든 집계 자료만 보관함으로 옮깁니다. 원거래는 수정·삭제하지 않습니다.
단일 영수증 테스트는 전체 집계를 변경하지 않습니다.

`DASHBOARD_SUMMARY_BLOCK_ID`는 자동 갱신하는 요약 콜아웃입니다.
콜아웃 또는 paragraph 자식의 문구가 각각 `전체 사용액`, `회계 처리 완료`로 시작해야 합니다.
일반 실행은 이 두 숫자 문구만 갱신하며, 다른 안내·본문은 변경하지 않습니다.
구조나 안내 문구가 달라지면 자동으로 덮어쓰지 않고 작업을 실패시켜 운영자가 확인하도록 합니다.
변경 없는 숫자는 다시 쓰지 않습니다.

## 운영 확인

Drive 파일 정리는 `DRIVE_ORGANIZE_ENABLED=false`를 유지합니다.
예약 정상 여부는 실행 이벤트가 `schedule`인 기록의 작업 결과와 집계 로그로 확인합니다.
수동 `workflow_dispatch` 성공을 예약 성공으로 보고하지 않습니다.
GitHub 예약 실행은 지연될 수 있으므로 정확한 실시간 업로드 감지는 보장하지 않습니다.
정확한 트리거가 필요해지면 별도 변경으로 Drive 알림과 지속 실행기를 도입합니다.
