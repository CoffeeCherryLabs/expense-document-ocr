# 주간 증빙 정리와 보고

OCR 접수와 Drive 파일 정리를 별도 실행기로 운영합니다. OCR 실행기에는 이동 경로가 없으며
기존 `DRIVE_ORGANIZE_ENABLED`가 true여도 파일을 이동하지 않습니다.
주간 workflow는 매주 월요일 10:13 KST(`13 1 * * 1` UTC)로 설정합니다.
GitHub 예약은 지연·누락될 수 있으므로 설정 시각과 실제 `schedule` 완료를 구분합니다.

## 이동 전 미리보기

`WEEKLY_ORGANIZATION_REPORT_PAGE_ID`는 기존 회사 Notion 권한 아래의 보고 페이지입니다.
처음에는 `WEEKLY_DRIVE_APPLY_ENABLED=false`로 실행해 대상과 보류 목록만 보고합니다.
파일명·원본 링크·개별 사유는 회사 Notion에만 기록합니다. 공개 Actions 로그·Summary에는
개수만 기록하며 영수증·판독 JSON·토큰·개별 거래를 artifact로 업로드하지 않습니다.
미리보기는 파일 다운로드, Vision OCR, 지출 검토 실행, Drive 쓰기를 하지 않습니다.

보고 페이지 첫 문단의 `최근 주간 점검:`을 최신 결과로 갱신하고,
실행마다 별도 보고를 누적합니다. 같은 GitHub run ID의 보고가 있으면 rerun을 중단하여
결과가 불확실한 쓰기나 이동을 반복하지 않습니다. 기존 보고의 숫자는 조회 시점의 스냅샷이며
실제 이동 결과는 실행 결과 문단에서 확인합니다.

## 이동 대상 조건

- 접수 기록 1개, OCR 상태 판독 완료, 확인 유형 접수 완료, 판독 오류 없음.
- 연결 지출 1개, 담당자가 원본 대조 완료·사용자 확인을 모두 체크.
- 취소·반려·환불·중복 청구 표시 없음.
- 파일 변경 시각·SHA256 판독 근거 존재, 확인한 지출과 판독 사용처·사용일·금액·승인번호·통화 일치.
- 지원 파일, 유효한 날짜, 원화 정수 금액과 승인번호. 참고 사진·unknown 판독은 제외.
- 최상위 폴더 또는 그 바로 아래 업로드대기 폴더에 있는 파일만 이동.

이미 다른 하위 폴더에 있는 파일은 다시 정리하지 않습니다. 날짜별 폴더에 있다는 사실이나
수신함의 정리 완료만으로 사람의 확인이 끝났다고 추정하지 않습니다.
체크박스는 회계 승인·지급·RCMS 등록과 별개이며 자동으로 체크하지 않습니다.
OCR 대조가 끝났지만 카드·참석자·업무 목적 등이 미확정이면 담당자가 확인을 완료하기 전까지 보류합니다.

## 실제 이동과 복구

사용자가 미리보기 목록과 기준을 확인한 후 주간 이동 스위치를 true로 변경합니다.
현재 레코드를 이동 직전에 다시 읽고, 원본 metadata를 재확인합니다.
대상 폴더의 권한 목록이 원본과 다르거나 확인할 수 없으면 이동하지 않습니다.
연도/월/사용일 폴더와 결정론적 이름을 사용해 Drive 파일 ID·원본 링크를 유지합니다.
사전에 증빙 페이지에 planned 이력을 기록하고, 실제 위치·이름·권한을 읽어 검증한 뒤 completed 이력을 남깁니다.
증빙의 파일명과 Drive 수정시각만 갱신하고 금액·소유자·회계 상태는 수정하지 않습니다.

오류는 재시도하지 않고 중단합니다. 마지막 이력이 completed가 아니면 다음 이동도 보류합니다.
원격 결과가 불확실할 때는 실제 Drive 위치와 Notion 이력을 먼저 대조합니다.
중복 파일이나 참고 사진을 삭제하지 않으며 sharing/ownership API도 호출하지 않습니다.
원본과 달라진 권한이 관측되면 운영자가 먼저 복구해야 합니다.

OCR과 주간 작업은 `expense-drive-sync` concurrency 그룹을 공유합니다.
기존 OCR 스위치 `EXPENSE_SYNC_ENABLED=false`는 두 작업을 모두 중단합니다.
주간 이동만 중단하려면 `WEEKLY_DRIVE_APPLY_ENABLED=false`로 변경합니다. 보고는 계속됩니다.

## 화면과 통합 방향

현재는 기존 지출·증빙 DB와 간단한 Notion 보고로 운영합니다. 별도 업무 앱이나 독립 원장을 만들지 않습니다.
상단에는 대상·보류·참고 사진·실패 개수, 상세에는 파일별 다음 작업과 원본 링크,
실행별 보고와 증빙별 이력을 둡니다. 이미 만든 지출 금액·캘린더·그래프는 기존 대시보드에서 재사용합니다.
즉시 이메일/Slack 송신이나 Notion AI 유료 agent를 추가하지 않습니다.
주간 보고가 보완 항목을 드러내며, workflow 실패 상태는 별도로 점검합니다.

나중에 자산관리와 통합할 때는 증빙의 Drive ID, Notion 증빙/지출 관계, planned/completed 이벤트를 연결합니다.
구매 증빙과 자산 승인·등록을 같은 것으로 취급하지 않습니다. 이 기록을 재사용하되 개인정보 원본을 공개 Git에 복제하지 않습니다.

검증: 가상 데이터로 human gate, 사진·오류·원본 변경·거래 충돌 제외,
권한 불일치 차단, durable audit 순서, 미리보기의 OCR·Drive 쓰기 금지를 검사합니다.
실제 주간 `schedule`과 실제 이동은 코드 테스트·수동 미리보기와 별도로 확인합니다.
